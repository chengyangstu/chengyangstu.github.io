第一章　先决定要回答什么物理问题

学习目标：把“加速 PIC”拆成可检验的物理目标、适用模型与计算规模。

先理解：模型、求解器与诊断

物理模型规定保留哪些过程，例如把等离子体看成流体，或保留粒子速度分布；数值求解器把这些方程变成有限次计算；诊断从输出中提取重联率、能量等可比较的量。GPU 加速通常改变求解器的执行方式，不能自动补回模型省略的物理。

PIC 是 Particle-in-Cell：用许多带权重的计算粒子描述分布，在空间网格上保存场，两者通过沉积和插值联系。MHD（磁流体力学）主要演化密度、流速、压强和磁场等流体量；回旋动理学则在受控排序下去掉快速回旋相位。先说清研究量需要哪一类描述，再选择代码。

1.1　加速的对象是一项科学判断

假设你关心电子尺度耗散区中的非理想电场。需要的输出可能是电子压强张量散度与惯性项，而不是一张漂亮的磁力线图。若你关心托卡马克微撕裂引起的电子热输运，需要的则是线性增长率、模结构、磁随机化与热通量。两类问题都包含“重联”，但它们要求保留的频率、空间尺度、几何和自由能来源不同。

动手前写一页“模型契约”：研究量是什么，哪些尺度必须解析，忽略了哪些过程，数值误差如何影响最后的判断。计算越快，越容易把一个不适用模型扫描得很精细。先用物理排序控制计算成本，再用硬件优化降低单位成本。

1.2　三层成果，而不是一次写完大程序

第一层是教学程序：你能解释每个数组和时间层，能从测试发现错误。第二层是基准程序：用明确边界与参数复现已发表结果，比较收敛而不是逐粒子轨道。第三层才是研究程序：在成熟代码或充分验证的自研代码上改变一个物理假设，给出误差与代价。教材附带的代码属于第一层；最后几章给出到第二、三层的路线。

建议保留三条工作线：reference/ 保存小规模可读版本；gpu/ 保存等价实现；runs/ 保存输入、版本和诊断。它们是学习时的目录建议，不必先搭建复杂软件框架。CPU 与 GPU 必须使用相同方程、粒子权重和边界，才能解释性能差异。

第二章　量纲、尺度与显存预算

学习目标：在编译前估计模拟的时间步、网格与粒子数量。

先理解：归一化与分辨率

归一化就是选一把“标尺”：若长度标尺为 \(d_i\)，代码中的 \(x=2\) 表示物理长度 \(2d_i\)。网格间距是相邻采样位置的距离，时间步是两次推进之间的间隔；它们越小，通常能解析越细的结构，但数组和迭代次数也会增加。

FP32 与 FP64 分别用 32、64 位存储一个浮点数，即通常每个数占 4、8 字节。精度是可分辨数字的能力，显存是设备可保存数据的容量；两者都不是“网格够细”的同义词。FFT 是快速傅里叶变换；ghost cell 是分区边缘保存邻居数据的附加网格点，后文会逐项解释其额外内存。

2.1　把归一化写在输入文件最前面

以背景密度 \(n_0\)、重联磁场 \(B_0\) 和离子质量 \(m_i\) 定义阿尔芬速度 \(v_A\)。常用离子尺度归一化是长度 \(d_i\)、时间 \(\Omega_i^{-1}\)、速度 \(v_A\)、磁场 \(B_0\)、电场 \(v_AB_0\)。因为 \(d_i\Omega_i=v_A\)，量纲转换可以直接交叉检查。SI 制与代码归一化制不能混写。

\[\omega_{ps}=\sqrt{\frac{n_0q_s^2}{\varepsilon_0m_s}},\qquad d_s=\frac{c}{\omega_{ps}}\]\[\Omega_s=\frac{|q_s|B_0}{m_s},\qquad v_A=\frac{B_0}{\sqrt{\mu_0n_0m_i}}\]\[\lambda_{De}=\sqrt{\frac{\varepsilon_0T_e}{n_0e^2}},\qquad \beta_s=\frac{2\mu_0n_0T_s}{B_0^2}\]

这里 \(T\) 以能量单位表示；若用开尔文须补 \(k_B\)。热速度也有两种常见定义：\(\sqrt{T/m}\) 与 \(\sqrt{2T/m}\)。本书静电参考程序使用前者，即一维 Maxwell 分布的标准差。记录定义比记住某个数字更重要，尤其在比较 \(\lambda_D\)、回旋半径和文献温度时。

2.2　网格可放入显存，不代表能解析物理

普通显式电磁 PIC 要同时处理场的 CFL 条件、电子振荡、回旋运动和有限网格误差。对均匀 Yee 网格，一个场传播限制是 \(c\Delta t\allowbreak\sqrt{\Delta x^{-2}+\Delta y^{-2}+\Delta z^{-2}}\le1\)。其他约束还依赖推进器、形状函数、温度、滤波和物理目标；不要把“\(\Delta t\) 小于一个固定常数”当作所有 PIC 方法的定理。

降低 \(m_i/m_e\) 或 \(c/v_A\) 可以降低成本，但会改变尺度分离。质量比从 25 改到 100，电子惯性长度相对离子长度会缩小一半。若保持网格不变，你其实改变了解析电子层的能力。参数扫描必须区分物理参数变化与分辨率变化。

2.3　先做一张字节账本

2D3V 的粒子通常保存 x、y、\(v_x\)、\(v_y\)、\(v_z\)；还可能保存权重、旧位置、ID、排序键与通信缓冲。按 3 个位置、3 个速度、1 个权重的 FP32 存储估算，仅主体就有 28 字节/粒子。1024×512 网格、每物种每格 100 粒子、两个物种，共约 1.05 亿粒子，主体约 2.94 GB（十进制），尚未计入排序副本与临时数组。

本机 4 GB 显存应从 64–128 个网格的一维练习，以及 64×32 或 128×64 的二维教学问题开始，实际空闲显存还受桌面占用影响。全电子尺度、大质量比、长时间三维重联需要重新预算，通常转移到集群。先估算每步时间 × 总步数，再决定是否跑参数扫描。

第三章　建立可以复现的 CUDA 环境

学习目标：区分驱动、Toolkit、编译器与设备能力，完成第一份运行记录。

先理解：编译与运行是两步

你写的 .cu 是文本源码；编译器把它转换成可执行程序，其中包含主机与设备所需代码。执行 nvcc ... -o saxpy 是编译，执行 ./saxpy 才是运行。主机（host）通常指 CPU 及其内存，设备（device）通常指 GPU 及其显存；程序两边都可能工作。

本书云端命令以 Linux shell 为主；Windows 的程序名、路径与终端启动方式可能不同。看到“找不到 nvcc”先检查工具链安装及 PATH，看到“找不到 saxpy”先检查编译是否成功与当前目录，看到运行时报设备错误再查驱动和 GPU 可见性，不要把三类问题混成一种。

3.1　四个组件，四种不同的问题

驱动负责操作系统与设备通信；CUDA Toolkit 提供编译器、运行时、库和开发工具；主机 C++ 编译器处理 CPU 代码；GPU 的计算能力决定可用指令与资源。nvidia-smi 显示的 CUDA 支持版本不能证明 nvcc 已安装。本机检查时驱动能识别 RTX 2050，但命令路径中未找到 nvcc。

Windows 原生路线需要官方支持的 Visual Studio C++ 工具链；Linux / WSL2 路线更接近大多数科研集群。WSL 使用 Windows 侧的 NVIDIA 驱动，安装步骤应遵循 NVIDIA WSL 指南，避免把普通 Linux 驱动安装流程直接复制进去。本文不固定未来版本号，先核对当前 Toolkit 的主机编译器支持矩阵，再安装匹配组合。

nvidia-smi
nvcc --version
# 在 CUDA Toolkit 与支持的主机编译器配置完成后：
nvcc -O3 -lineinfo -std=c++17 saxpy.cu -o saxpy
# Linux / WSL
./saxpy 1048576
# Windows PowerShell
.\saxpy.exe 1048576

3.2　正确运行优先于追逐架构选项

第一次先用工具链默认设置完成编译和正确性检查。之后查询设备计算能力，再选择匹配的 -arch / -gencode；不要照抄另一个数据中心 GPU 的架构参数。发布科研二进制时记录目标架构、驱动、工具链、编译选项与库版本。目标集群已有软件模块时，优先使用管理员提供且经过验证的组合。

-lineinfo 让性能工具把内核位置映射回源码；-G 是设备调试选项，会明显改变生成代码，不应用来做正式性能比较。初学阶段不启用 --use_fast_math。先知道误差来自哪个运算，再判断近似数学是否允许。

代码里的 CUDA(call) 是本站 common.cuh 定义的错误检查宏，不是 CUDA 语言自带的新语法。它执行括号中的 API 调用，检查返回码，失败时报告位置并停止。先保留这层检查，出错时才知道是分配、传输、启动还是执行阶段失败。

3.3　建立实验日志

每次实验保存输入文件、Git 提交号、随机种子、设备名称、数值精度、运行命令和输出摘要。相同源码在不同粒子顺序、归约顺序和编译设置下，可能得到不同的最低位结果。可复现通常指统计量与物理结论在给定误差内一致，而非每个粒子的二进制状态永远相同。

第四章　面向数值计算的 C++ 与数据设计

学习目标：能够阅读数组内核，明确索引、所有权、边界和误差度量。

先理解：数组、指针和数据排列

数组是一段按顺序存放的数据，x[7] 表示第八个位置值；指针保存地址，不能仅从地址知道数组长度，所以函数常同时接收 x 与 n。主机地址与设备地址必须对应正确的分配，普通 CPU 指针不能直接当作独立显存上的数组使用。

AoS（结构体数组）把一个粒子的各属性放一起，例如 {x0,v0},{x1,v1}；SoA（数组结构）把同一属性连续放一起，例如 x0,x1,... 和 v0,v1,...。当相邻线程都读各自的 x 时，SoA 更容易形成连续访问；这是一种布局选择，不改变粒子的物理含义。

4.1　先掌握够用的一小部分 C++

起步需要的是变量类型、函数、循环、指针、引用、结构体、std::vector 与头文件，不是模板元编程。CPU 容器可以管理主机数组，但 GPU 内核接收的原始指针必须指向设备可访问的数据。sizeof(pointer) 不等于数组字节数；分配字节数应写成元素数量乘元素大小，并用足够宽的整数类型处理大规模数组。

设网格在 x 方向有 Nₓ 点，行优先二维索引可写成 j * Nx + i。最常见错误不是微分公式，而是内部点与含 ghost 的总跨度混用。给每个数组写下注释：物理量、空间位置、时间层、形状、单位。电场三个分量的 Yee 位置不同，因此不能仅凭它们长度相似就使用同一套插值索引。

// row-major: x is contiguous; pitch includes ghost cells when present.
size_t index = size_t(j) * pitch + i;
double relative_L2 = std::sqrt(error_squared / reference_squared);
// reference near zero: also report an absolute error scale.

4.2　从数组布局看粒子操作

结构体数组 AoS 把一个粒子的全部属性放在一起；数组结构 SoA 把所有粒子的 x 放在一段连续内存，所有 \(v_x\) 放在另一段。GPU 中相邻线程常处理相邻粒子，SoA 使它们同时读取同一属性时更容易形成连续访问。AoSoA 则按小组组织粒子，常出现在可移植高性能框架中。是否更快仍要针对实际推进、沉积和迁移访问测量。

不要在每步重新创建粒子数组。把容量与当前粒子数分开：迁移或注入可以改变数量，但不应反复分配整个空间。教学初期先固定粒子数，周期边界直接折回位置；涉及开放边界后，再增加删除、压缩、注入和随机数状态。

4.3　比较结果时报告什么

对场数组报告最大绝对误差和相对 \(L_2\) 误差；对离散守恒报告相对初值的漂移；对增长率报告拟合窗口、分辨率和随机种子变化。零参考量不能直接放到分母。为每个阈值写明物理量和归一化尺度，例如“电荷连续性残差相对 \(n_0e/\Delta t\)”，而不是一个没有单位的神秘 1e-6。

第五章　线程、线程块与第一个内核

学习目标：理解执行索引与异步启动，写出覆盖任意数组长度的内核。

5.1　从一个线程到整个 grid

先回想 CPU 上的 for (int i = 0; i < n; ++i)：一个执行流程依次处理数组元素。CUDA 的 kernel（内核函数）描述一个线程要做的工作；启动后，许多线程分别执行同一段代码，用各自的编号选择数据。例如第 7 个线程读取第 7 个粒子的位置和速度，再写回它的新位置。

thread（线程）是这个执行实例，每个线程有自己的局部变量与逻辑编号。block（线程块）是一组线程，它们可以使用同一块共享内存，并在合适位置进行块内同步。grid（线程网格）是一次内核启动所包含的全部线程块。程序员指定块的数量与每块线程数，运行时和硬件安排实际执行。

这里的 grid 是执行工作的分组，PIC 中保存电场、磁场的物理网格是空间的离散，两者不要混淆。你可以让一个线程负责一个粒子，也可以让它负责一个场网格点；数据分工由索引规则决定，不由单词 grid 自动决定。

5.1.1　四个内置名字分别表示什么

CUDA 已经为每个线程提供编号，不需要你给这些变量赋值。先只使用一维排列，名字后的 .x 表示第一维；二维和三维还会使用 .y、.z。

threadIdx.x
当前线程在本块内的编号，从 0 开始。每块 4 个线程时，各块内部都会重复出现 0、1、2、3。
blockIdx.x
当前块在 grid 内的编号。图中三个块的编号分别是 0、1、2。
blockDim.x
每块沿 x 方向的线程数。本例所有块都是 4，不是当前线程的编号。
gridDim.x
grid 沿 x 方向有多少个块。本例是 3，不是线程总数。

要得到整个数组中的编号，先跳过前面的完整块，再加上块内位置：\(i=bT+t\)，其中 \(b\) 是块编号，\(T\) 是每块线程数，\(t\) 是块内线程编号。因此 block 1 中的 thread 2 对应 \(i=1\times4+2=6\)。代码就是 blockIdx.x * blockDim.x + threadIdx.x。

5.1.2　把十个元素真的分下去

若有 \(N=10\) 个元素，每块设 \(T=4\) 个线程，需要 \(\lceil N/T\rceil=3\) 个块。向上取整在正整数代码中常写为 (n + threads - 1) / threads。这次启动包含 12 个逻辑线程，但只有索引 0–9 有效；最后两个线程必须通过边界判断跳过，不能读取不存在的第 10、11 号元素。

__global__ void advance(float* x, const float* vx, int n, float dt) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) {
        x[i] += dt * vx[i];
    }
}

// Host code: d_x and d_vx must already point to allocated device arrays.
int n = 10;
int threads = 4;                         // Teaching example, not a tuned value.
int blocks = (n + threads - 1) / threads; // 3 blocks
advance<<<blocks, threads>>>(d_x, d_vx, n, dt);
CUDA(cudaGetLastError());
CUDA(cudaDeviceSynchronize());           // Wait while learning/debugging.

__global__ 声明这是可从主机启动的 GPU 内核；float* x 是位置数组的地址，const float* vx 表示此函数不通过该指针修改速度。<<<blocks, threads>>> 是启动配置，括号里的 (d_x, d_vx, n, dt) 才是传给函数的数据参数。变量名前的 d_ 只是提示“设备数组”的命名习惯，不会自动把内存搬到 GPU。

上面是片段，需要前文的设备分配、初始化与 CUDA 错误检查宏才能编译。完整程序可对照 saxpy.cu 和 common.cuh。每块 4 线程是为了能在纸上画出来；实际训练先试 128 或 256，再根据资源与计时调整。

5.1.3　为什么还有 grid-stride loop

另一种安排是只启动较少的线程，让一个线程处理多轮数据。所有已启动线程第一轮各处理一个索引，下一轮统一向前跳过线程总数 \(S=T\times G\)，其中 \(G\) 为块数。例如 2 块、每块 4 线程时跨度为 8：逻辑线程 0 处理索引 0、8，线程 1 处理 1、9，其余只处理 2–7。

int first = blockIdx.x * blockDim.x + threadIdx.x;
int stride = blockDim.x * gridDim.x;
for (int i = first; i < n; i += stride) {
    x[i] += dt * vx[i];
}

这就是 grid-stride loop。它把问题大小与启动线程总数分开，仍然要保留 i < n。上面的 int 只适合本课程小规模练习；处理超过其索引范围的大数组时，应同时检查索引、跨度和分配字节数的整数类型，不能只改一个变量。

5.1.4　warp 与 SM：分组怎样进入硬件

SM（Streaming Multiprocessor，流式多处理器）是 GPU 上执行线程块的硬件资源。普通线程块被安排到一个 SM 上执行，SM 可以驻留多个块，但数量受寄存器、共享内存和线程等资源限制。GPU 不会保证 block 0 先完成，也不会保证全部块同时驻留。

warp（线程束）是块内按连续线程编号组成的 32 线程组；本书面向的 NVIDIA CUDA 设备使用这一宽度。一个 256 线程块会分成 8 个 warp。warp 不是 block 的同义词，更不是 32 个粒子物理上必须同步运动。如果分支条件让组内线程走不同路径，会影响执行效率；正确性仍要依靠明确的同步与数据依赖，不能假设同一 warp 内可以随意省略同步。

纸上检查：把上图改成 17 个元素、每块 8 线程，写出块数、索引 13 的块内编号、哪些线程跳过。答案是 3 块；索引 13 位于 block 1、thread 5；逻辑索引 17–23 跳过。再用 2 块的 grid-stride loop 列出线程 0、1 的工作，确认没有遗漏或重复。定义可对照 NVIDIA 官方 Programming Model。

5.2　主机返回，不等于设备完成

内核启动通常异步返回。CPU 时钟包围一次启动，测到的可能只是提交开销。调试时，启动后检查立即错误，再同步捕获执行错误。正式流水线尽量只在确实需要结果的地方同步；同一 stream（设备操作的有序队列）内的顺序可表达许多依赖，无需每个内核之间都让 CPU 等待。

5.3　SAXPY 是显存实验，不是 PIC 性能证明

本站例子计算 out=2x+y，逻辑上每元素读两个 FP32 并写一个 FP32，即 12 字节，约 2 次浮点运算。用这个可解释的工作量建立计时习惯，然后观察小数组的启动开销与大数组的存储流量。有效带宽是算法字节数除以内核时间；缓存命中时它不等于 DRAM 的实际传输带宽。

程序先预热，随后用 CUDA events（记录设备执行进度的事件标记）计时多次相同运算，最后回传结果验证。这避免把首次初始化混到稳定内核时间中，但也明确排除了 H2D（主机到设备）/D2H（设备到主机）数据传输与内存分配。报告性能时必须同时注明这一点。

第六章　让数据移动得少一点

学习目标：把寄存器、共享内存、缓存、显存与主机传输放进同一份成本分析。

先理解：三种常用设备存储

寄存器通常保存一个线程正在使用的少量局部值；共享内存是一个线程块内可协作使用的临时空间；全局内存保存较大的设备数组，可跨内核保留。它们的容量、作用域和访问代价不同。“local memory”虽然名字叫局部，通常对应设备内存中的线程私有存储，不能误当成快速片上寄存器。

合并访问（coalescing）指同一 warp 的内存请求能够组织成较少的内存事务。相邻线程读取连续的 x 数组通常更有利；若每个线程跳过很长距离，就可能触及更多存储区段。tile 是人为划分的小片数据，例如先把一片网格场放入共享内存，让附近粒子重复使用；只有复用收益超过装载与同步开销时才值得做。

6.1　连续访问是起点，复用才是理由

相邻线程访问相邻地址通常更有利于合并访存。因此，把 x[i]、\(v_x\)[i] 等粒子属性分别连续存放，是一个容易验证的起点。若把线程映射到二维网格，优先让同一 warp 的线程沿连续维移动。访问步幅、对齐、有效线程数与实际缓存行为都会影响最后结果。

共享内存适合多个线程重复使用同一块数据，例如 tile 内网格场的复用或局部沉积。它同时引入装载、同步、容量与 bank conflict 等成本。bank 是共享内存内部可并行服务的存储分组；同一 warp 对同一 bank 中不同地址的访问发生冲突时，可能需要分批服务。同址读取的广播情形应另行区分。对于没有复用的一次性向量读取，把数据先搬到共享内存往往只是增加一次中转。判断是否使用共享内存前，先数一个网格值被多少粒子重复读取。

6.2　寄存器不够时会发生什么

Boris 推进需要多个速度、电场、磁场和临时向量。保留过多中间值可能提高寄存器需求，限制活跃线程块；溢出还可能产生设备内存访问。占用率 occupancy 通常描述活跃 warp 数相对设备允许上限的比例；它帮助判断是否有足够工作隐藏等待，但不是越高就必然越快的性能目标。一个寄存器稍多但少读几次显存的内核，可能比“高占用率”版本更快。

把推进、插值、边界和沉积全融合成一个巨大内核，可以减少读写，但也可能提高寄存器压力并使分支更复杂。先建立分开的正确版本，找到实际昂贵的数据往返，再尝试一次有理由的融合。每次只改一项，保留性能与误差对照。

6.3　PIC 的主要数据应留在设备上

一个时间步通常是场插值、粒子推进、沉积、场更新和边界处理。若每步都把全部粒子拷回 CPU，GPU 内核再快也会被传输吞掉。设备上完成电荷、能量、谱模等归约后，只回传少量诊断。全粒子输出应按研究需要稀疏采样，检查点也应与物理诊断区分。

for (int step = 0; step < steps; ++step) {

第七章　同步、归约与原子操作

学习目标：避免数据竞争，正确计算总电荷和能量，并理解浮点非确定性。

先理解：竞争、同步与归约

如果两个线程都读到网格值 0，各自在本地加 1 后都写回 1，正确答案 2 就丢了，这叫数据竞争。原子加把该地址的一次“读取—相加—写回”作为不可被同类操作插入的更新，避免这类丢失。原子操作不等于“整个算法守恒”，也不保证浮点加法的顺序。

同步是让某些参与者在依赖成立后继续；块内屏障要求该块应参与的线程都到达。归约（reduction）把许多值合成一个值，例如先算各小组电荷和，再合成总电荷。扫描（prefix sum）则给每个位置一个此前元素的累积和，常用于把粒子分配到排序后的数组位置，二者输出不同。

7.1　为什么沉积容易错

两个粒子可能同时向同一网格点累加。普通 rho[j] += contribution 包含读、加、写，多个线程可能互相覆盖。atomicAdd 保护该地址的一次更新，是最容易建立正确 GPU 基线的选择。但它不能自动保证整个 PIC 算法的离散电荷连续性，也不保证每次浮点累加顺序一致。

同样，块内的 __syncthreads() 只同步当前线程块。它不是全网格屏障。不要让部分线程提前 return，而其余线程随后到达必须共同参与的屏障。若一个阶段需要全体线程写完，最直观的基线是在同一 stream 中使用两个顺序内核。

7.2　归约是树，不是一百万次串行相加

总动能 \(K=\sum_p\tfrac12 m_p w_p|\mathbf v_p|^2\) 是一个归约问题。教学实现可以让每个线程局部累加，然后块内归约，最后归约各块结果。warp shuffle 可交换线程寄存器值，但需要正确处理参与掩码和不足一个 warp 的尾部。生产实现优先评估 CUB 的归约与扫描，不必维护多个脆弱的手写版本。

浮点加法不满足结合律。即使所有 atomic 都正确，不同线程调度仍可能改变最低位。对跨许多数量级的能量总和，考虑 FP64 累加、分块或补偿求和，再量化误差。不同设备是否高效支持某种精度要查目标架构，而不能从“有 FP64 类型”推断吞吐。

7.3　最小反例胜过大规模重联调试

把所有粒子放在同一单元，最容易暴露沉积冲突与累加精度问题；把粒子放在边界，最容易暴露索引问题；令 N=33，最容易暴露 warp 尾部处理问题。先用这些故意不友好的数据集检查内核，再使用均匀随机分布测性能。

第八章　用证据定位性能瓶颈

学习目标：结合时间线、内核指标、Roofline 与端到端加速比做一次完整性能分析。

先理解：延迟、带宽与吞吐率

延迟是一次操作从发起到完成要多久；带宽是每秒能传多少字节；算术吞吐率是每秒能完成多少算术操作。很小的内核可能主要付启动延迟，大数组推进可能主要付访存代价。GPU 利用率高只能说明设备忙，不能告诉你它在忙着做有用算术还是等待数据。

Profiler 是性能分析工具。Nsight Systems 用时间线看 CPU、GPU 与通信怎样衔接；Nsight Compute 深入某个内核看访存与执行指标。先测完整一步，再拆分最贵部分；采样工具自身会增加开销，所以性能报告还需给不带分析工具的独立计时。

8.1　先看整步，再看最贵内核

先用 Nsight Systems 看 CPU、拷贝、GPU、同步和 MPI 的时间关系。若 GPU 经常空闲，可能是提交、通信或 I/O 问题，此时先优化某个已很快的算术表达式不会解决整体瓶颈。再用 Nsight Compute 查看最昂贵内核的访存、占用资源和指令情况。

nsys profile --trace=cuda,nvtx -o timeline ./saxpy 16777216
ncu --set basic ./saxpy 16777216
# Profiling changes execution; report final timing from an unprofiled run too.

不同系统的权限与工具支持不同；命令不能运行时先查官方部署说明。一个采样失败不代表程序没有瓶颈。可先用事件计时与 CPU 墙钟建立粗粒度性能表，再在目标集群获得正确的性能计数器访问。

8.2　Roofline 是上界模型

运算强度 \(I\) 是完成的浮点运算数除以传输字节数，单位 FLOP/byte；\(B_{\mathrm{memory}}\) 是相应内存层级的带宽。下式中的 \(f\) 是原总时间中可加速部分的比例，\(S_{\mathrm{kernel}}\) 是该部分的加速倍数。例如原来只占 20% 时间的内核即使无限快，总体也最多加速到 \(1/(1-0.2)=1.25\) 倍。

\[I=\frac{N_{\mathrm{FLOP}}}{N_{\mathrm{byte}}}\]\[P\leq\min(P_{\mathrm{peak}},B_{\mathrm{memory}}I)\]\[S_{\mathrm{total}}=\frac{1}{(1-f)+f/S_{\mathrm{kernel}}}\]

第一式的算术强度必须与带宽层级一致：基于 DRAM 字节的强度应与 DRAM 带宽比较。PIC 沉积还可能受原子冲突、散乱访问和负载不均衡限制，不能只按浮点乘加数量预测。第三式是 Amdahl 估算：若推进只占总时间 30%，即使它快十倍，总加速也只有约 1.37 倍。

8.3　怎样写一张可信的性能表

报告 GPU、精度、网格、粒子数、每格粒子数、算法、诊断频率和计时边界。区分“粒子推进吞吐”与“整个 PIC 周期粒子更新吞吐”。预热后独立运行多次，报告中位数和散布；同一结果必须同时给出正确性指标。不用一台 GPU 的优化程序与单线程 Python 作比较后宣称通用科研加速比。

第九章　从 Vlasov 方程到宏粒子

学习目标：理解 PIC 近似了什么，以及权重、形状函数和噪声从哪里来。

先理解：分布函数与宏粒子

分布函数 \(f_s(\mathbf x,\mathbf v,t)\) 告诉你物种 s 在某个位置、某段速度范围内有多少粒子；它同时依赖位置和速度，所以生活在相空间中。对速度积分得到密度。一个 PIC 宏粒子代表一份带权重的分布样本，不是只模拟一个真实电子；权重决定它对电荷、质量和诊断的贡献。

沉积（scatter/deposit）是把粒子携带的电荷或电流分配给附近网格；插值（gather）是从网格取回粒子位置处的场。CIC（Cloud-in-Cell）用线性权重进行这种分配。例如粒子在左节点右侧 0.3 个网格间距处，左、右节点分别得到 0.7、0.3 的权重，和仍为 1。

9.1　沿特征线移动分布函数

\[\begin{aligned}\frac{\partial f_s}{\partial t}+\mathbf v\cdot\nabla_{\mathbf x}f_s&\\+\frac{q_s}{m_s}(\mathbf E+\mathbf v\times\mathbf B)\cdot\nabla_{\mathbf v}f_s&=0\end{aligned}\]\[\dot{\mathbf x}=\mathbf v,\qquad \dot{\mathbf v}=\frac qm(\mathbf E+\mathbf v\times\mathbf B)\]

无碰撞 Vlasov 方程说明分布函数沿相空间特征线保持不变。PIC 用有限数量的带权样本表示分布，再由这些样本计算网格上的矩。宏粒子不是一颗被放大的真实电子，而是一份相空间样本。若一个宏粒子代表 w 个真实粒子，则其电荷和质量都乘 w，因此推进中的 Q/M 仍是物种的 q/m。

位置沉积通常使用有限宽度形状函数。用归一化的 S 表示粒子对网格的分配，电荷密度可写成网格体积归一化后的 \(\sum_pQ_pS_i(x_p)\)。网格场再用插值作用于粒子。形状函数、场离散和时间推进共同决定数值性质，不能分别选“看上去更平滑”的方案而不检查整体一致性。

9.2　用一个粒子推导 CIC

在一维均匀网格上，粒子位于 \(x_j\) 与 \(x_{j+1}\) 之间。令 \(\xi=(x-x_j)/\Delta x\)，则左点权重 \(1-\xi\)，右点权重 \(\xi\)。两者之和为 1，因此一个粒子的电荷不会凭空增加。密度需要除以 \(\Delta x\)；三维则除以单元体积。这一因子经常被错误地藏进权重，导致不同网格下比较失真。

\[\rho_j\mathrel{+}=\frac{Q_p(1-\xi)}{\Delta x},\qquad \rho_{j+1}\mathrel{+}=\frac{Q_p\xi}{\Delta x}\]\[E(x_p)=(1-\xi)E_j+\xi E_{j+1}\]

周期边界应先把位置折回 [0,L)，再计算索引。边界点 x=L 与 x=0 表示同一位置。GPU 上特别要测试负位置和跨越多个盒长的粒子，不能只处理“越过一点点”的情况。

9.3　粒子噪声不是实现错误的免罪符

独立随机采样时，许多统计误差随样本数的平方根改善，但实际 PIC 噪声还受形状函数、网格相关性、quiet start 和演化影响。增加每格粒子数与细化网格解决的是不同问题。若网格加倍而总粒子数固定，每格粒子数会下降，误差来源随之混合。

\(\delta f\) 方法围绕已知背景只表示扰动，有机会降低近背景问题的噪声，但需要推导权重演化与背景响应，不能把全 f 粒子的权重简单改成负数就当作 \(\delta f\)。先理解 full-f 的守恒和噪声，再进入低噪声扰动方法。

第十章　完成一个 1D1V 静电 PIC

学习目标：把沉积、泊松方程、插值与 leapfrog 连接成完整时间循环。

先理解：1D1V、谱空间与半步

1D1V 表示一个位置维度 x、一个速度维度 v，不是“只有一个粒子”。程序仍可有很多计算粒子和网格点。静电模型只求这里的电场响应，没有完整电磁波与磁重联；它足够简单，适合检查沉积、场求解和推进是否连接正确。

傅里叶变换把空间上的曲线写成不同波数正弦/余弦模式的叠加，在周期问题中，求导可转为乘 \(ik\)。leapfrog（蛙跳）把位置与速度错开半个时间步：位置在整数时刻，速度在半整数时刻。两者需要互相推进，所以初始化和能量诊断都要对齐时间，不能仅凭数组刚更新就把它当成同一时刻。

10.1　本章模型与归一化

参考程序采用周期一维电子动力学、静止均匀离子背景、无磁场和无碰撞。归一化后 \(n_0=e=m_e=\varepsilon_0=1\)，因此电子 \(q/m=-1\)，\(\omega_{pe}=1\)。盒长 \(L=4\pi\)，默认网格 64、每格 128 粒子。这个程序用于建立数值对照，不能描述磁重联。

电荷沉积为电子负密度加离子 +1 背景。周期泊松问题要求净电荷为零。程序记录沉积后尚未去均值的 mean_charge，场求解再去除舍入残差。若净电荷明显非零，应检查初始化或边界；不能靠去均值掩盖丢粒子或权重错误。

10.2　谱空间泊松求解的符号

\[\frac{\partial E}{\partial x}=\rho,\qquad ik\widehat E(k)=\widehat\rho(k)\]\[\widehat E(k)=\frac{\widehat\rho(k)}{ik}\ (k\ne0),\qquad\widehat E(0)=0\]

这与先求 \(\widehat\phi=\widehat\rho/k^2\)、再用 \(\widehat E=-ik\widehat\phi\) 一致。对 \(\rho=\sin x\)，解析场为 \(E=-\cos x\)，可以直接检查正负号。偶数网格的 Nyquist 模在这里设为零，以获得一致的实值谱微分约定；它不是一个可用于解析最短波长物理的自由通行证。

10.3　把速度的半步错位画出来

# x is x^n; vh is v^(n-1/2); e is E^n
a = -gather(x, e, L)
v_at_n = vh + 0.5 * dt * a   # diagnostics at integer time
vh += dt * a                # v^(n+1/2)
x = (x + dt * vh) % L       # x^(n+1)
rho = deposit(x, cells, L)
e = field(rho, L)           # E^(n+1)

输入通常给 \(v^0\)。为了启动 leapfrog，需要先构造 \(v^{-1/2}=v^0-a^0\Delta t/2\)。能量诊断则使用回到整数时刻的速度。若把半步动能和整数步场能直接相加，可能把时间错位当成真实能量变化。

第十一章　Boris 推进器与带电粒子轨道

学习目标：推导非相对论 Boris 旋转，分别验证能量、相位与漂移。

先理解：为何磁场推进需要特别处理

电场可以改变粒子速率，静态纯磁场中的洛伦兹力始终垂直速度，连续方程中只转方向、不改变动能。Boris 方法把电场加速与磁旋转拆开，以较低成本保持良好的轨道性质。它不是“时间步任意大都准确”，旋转角与连续轨道仍有离散误差。

式中的加号、减号上标表示推进过程的中间速度，不是正负电荷；\(n\pm1/2\) 才表示时间层。粗体 \(\mathbf t\)、\(\mathbf s\) 是根据磁场构造的无量纲旋转向量，\(\Delta t\) 才是时间步。把这些名字先区分开，后面的交叉乘积才能逐行核对。

11.1　电场半步、磁场旋转、电场半步

设当前位置插值得到 E 与 B。非相对论 Boris 方法先用电场加速半步，再对速度做一个保持长度的磁旋转，最后再加半步电场。这里 v 是速度，不是相对论动量；相对论推广中的 \(\gamma\) 与旋转参数不能直接省略。

\[\mathbf v^-=\mathbf v^{n-1/2}+\frac{q\Delta t}{2m}\mathbf E\]\[\mathbf t=\frac{q\Delta t}{2m}\mathbf B,\qquad\mathbf s=\frac{2\mathbf t}{1+\mathbf t\cdot\mathbf t}\]\[\mathbf v^\prime=\mathbf v^-+\mathbf v^-\times\mathbf t\]\[\mathbf v^+=\mathbf v^-+\mathbf v^\prime\times\mathbf s\]\[\mathbf v^{n+1/2}=\mathbf v^++\frac{q\Delta t}{2m}\mathbf E\]

纯磁场下，Cayley 旋转保持速度模长到浮点舍入误差；但它对应的单步转角是 \(2\arctan(\Omega\Delta t/2)\)，并不等于连续轨道的 \(\Omega\Delta t\)。于是“动能不漂移”与“轨道相位准确”是两种不同的测试。很大的时间步可能能量好看但相位错误。

11.2　从二维旋转练习到完整推进器

particles.cu 使用 E=0、B沿 z、\(q/m=-1\)，验证 \(v_x\)、\(v_y\) 的二维旋转。先和离散旋转角比较代码正确性，再和连续回旋角比较时间离散误差。这个文件还测试独立电荷沉积，但没有把轨道和场自洽连接。

把它推广到三分量时，手写叉乘并用至少三个方向的均匀 B 测试。再加入均匀电场：E∥B 时检查平行加速，E⊥B 时检查足够长时间平均的 \(\mathbf E\times\mathbf B\) 漂移。非均匀 B 中，磁矩只是适当缓变条件下的绝热不变量；不能在任意强梯度电流片里要求它严格守恒。

11.3　轨道测试如何支持重联研究

重联中电子可能经历弱磁化区、强电场、很窄的电流层。先把单粒子响应校准，可以排除“加热其实来自推进误差”的简单原因。但自洽模拟中的总能量还由场更新、沉积和边界决定。独立 Boris 测试通过，不等于整个电磁 PIC 能量守恒。

第十二章　Maxwell 方程与 Yee 网格

学习目标：理解空间与时间交错，构造保持离散散度结构的场推进。

先理解：交错网格与 CFL

交错网格把不同场分量放在不同空间位置，而不是把所有量都塞在单元中心。Yee 网格通过这类安排让旋度差分自然连接电场与磁场。ghost cell（幽灵单元）则在本地有效区域外保存邻居值，方便边界附近也使用同一套差分模板；它通常是数据副本，不是新增的物理体积。

CFL 条件约束离散算法每步传播信息的距离与网格间距的关系。对显式电磁场，光速、时间步和各方向网格间距都参与约束。满足它只是该离散场推进的稳定性条件之一，不意味着电子尺度、粒子轨道或有限网格误差都已满足要求。

12.1　交错排列是为了让算子相容

\[\mathbf B^{n+1/2}=\mathbf B^{n-1/2}-\Delta t\,\nabla_h\times\mathbf E^n\]\[\begin{aligned}\mathbf E^{n+1}={}&\mathbf E^n+c^2\Delta t\,\nabla_h\times\mathbf B^{n+1/2}\\&-\frac{\Delta t}{\varepsilon_0}\mathbf J^{n+1/2}\end{aligned}\]

Yee 网格把不同分量放在不同空间位置，使旋度使用邻近的交错差分。若边界与离散算子相容，离散散度作用于离散旋度为零。这种代数性质比“差分是二阶”更值得先验证：它是磁散度和 Gauss 约束演化的基础。

先画 2D 的一个单元，标明 \(E_x\)、\(E_y\)、\(E_z\)、\(B_x\)、\(B_y\)、\(B_z\) 与 J 的位置，再决定数组大小和 ghost 宽度。不同代码的标号约定可以不同，但你自己的旋度、插值、边界交换和诊断必须保持同一个约定。

12.2　一份明确的时间循环

  1. \(\mathbf E^n\)、\(\mathbf B^{n-1/2}\)
  2. 更新 \(\mathbf B^{n+1/2}\)
  3. 构造推进所需居中 \(\mathbf B^n\)
  4. v半步与x整步推进
  5. 路径沉积 \(\mathbf J^{n+1/2}\)
  6. 更新 \(\mathbf E^{n+1}\)

这里使用 \(\mathbf B^n\approx(\mathbf B^{n-1/2}+\mathbf B^{n+1/2})/2\) 为粒子提供时间居中的磁场。具体实现可以采用等价的半步组织方式，但必须完整写出初始化和最后一次诊断所在时刻。不要把来自两份代码的推进顺序各取一半拼接。

12.3　先传播真空波，再放进等离子体

\(\mathbf J=0\) 的真空波是场求解器最便宜的测试。周期平面波应按数值色散关系传播；改变 \(\Delta x\) 和 \(\Delta t\)，比较相位速度与振幅误差。脉冲经过周期边界后应正确回到域内。开放边界或吸收层需单独测反射系数，不能只凭屏幕上波离开就宣布无反射。

最后加入解析指定电流，检查 Ampère 项的符号和量纲，再接入粒子电流。ghost 数据交换后何时更新边界点应明确；MPI 通信顺序错误可能首先表现为边界附近异常加热。

第十三章　守恒电流沉积与 Gauss 约束

学习目标：从离散连续性理解为何 \(\mathbf J=q\mathbf v\) 的点采样通常不足以支撑电磁 PIC。

先理解：总电荷与局部连续性

所有网格电荷加起来没变，是全局总量检查；每个单元内电荷的变化等于净流入电流，是局部连续性。一个算法可能总量碰巧正确，但把电流沉积到了错误位置，导致 Gauss 约束逐步漂移。因此，守恒沉积要用粒子走过的路径解释每个单元电荷怎样变化。

残差（residual）就是把数值结果代回方程后剩下的不平衡量。它应带单位或清楚的归一化。残差小说明某个离散关系满足得好，还需要网格收敛检查才能判断这组离散方程是否准确表示了目标连续物理。

13.1　关键是离散连续性，而不只是总电荷

\[\frac{\rho^{n+1}-\rho^n}{\Delta t}+\nabla_h\cdot\mathbf J^{n+1/2}=0\]\[G^n=\nabla_h\cdot\mathbf E^n-\rho^n/\varepsilon_0\]\[\begin{aligned}G^{n+1}-G^n=-\frac{\Delta t}{\varepsilon_0}\Big[&\nabla_h\cdot\mathbf J^{n+1/2}\\&+\frac{\rho^{n+1}-\rho^n}{\Delta t}\Big]\end{aligned}\]

对 Ampère 更新取散度即可得到最后一行。如果电流与粒子位置变化不满足同一套离散连续性，即使总电荷在全域积分上不变，局部 Gauss 误差仍会积累。用原子操作正确累加一个不相容的电流公式，得到的仍然是不相容的电流。

守恒方法通过粒子从 \(\mathbf x^n\) 到 \(\mathbf x^{n+1}\) 的轨迹构造网格电流，让电荷形状的变化等于流出通量。跨单元、跨分区、跨周期边界的粒子必须保留正确路径信息。只保存折回后的两个端点，可能丢失真实穿越方向。

13.2　一维推导是理解多维方法的入口

\[J_{j+1/2}=J_{j-1/2}-\frac{\Delta x}{\Delta t}(\rho_j^{n+1}-\rho_j^n)\]

这是离散连续性在一维的递推关系，可以用作测试诊断。周期域中它只确定电流的空间变化，平均电流这个常数仍需由粒子运动确定。因此，仅用前缀和从密度变化反推出 J 并不是完整物理算法。它适合检查局部通量是否与你的沉积一致。

二维张量形状的变化可写成 \(\Delta(S_xS_y)=\Delta S_x\,\overline S_y+\overline S_x\,\Delta S_y\)。这展示了如何把电荷变化拆给不同方向电流。真正的多维实现还要处理形状阶数、跨单元路径和网格交错。应逐式阅读 Esirkepov 原文 并与成熟代码对照，不靠一行 \(\mathbf J=q\mathbf v\) 的直觉替代。

13.3　滤波也必须接受同一检查

对电流滤波可以减少噪声，但滤波算子、边界处理和密度处理应与离散连续性兼容。仅仅把 E 平滑后看到噪声消失，不说明误差被正确处理。使用散度清理时，也要报告清理前后的约束、引入的能量变化与清理参数。

训练 13 · 一个粒子的局部连续性

先在一维实现路径一致电流，测试留在单元内、跨一个单元、跨多个单元和周期穿越。再移植二维守恒沉积。对每个网格点计算连续性残差，而不仅是全域总和。

验收：舍入允许范围内满足所采用差分算子的连续性；Gauss 误差不出现无解释的长期增长。测量 GPU 优化前后同一个残差。本站 CIC 练习 只沉积电荷，不能用它替代本章电流算法。

必读论文：Esirkepov 的精确电荷守恒。进阶：EZ 沉积算法，关注它优化的是哪段路径处理及适用形状函数。

第十四章　从散乱粒子到完整 GPU PIC 周期

学习目标：用分箱、排序与局部累加改善沉积，同时保持粒子与网格耦合一致。

先理解：排序为什么能加速

粒子在物理上继续运动，但内存里的排列未必还按空间邻近。排序按所在单元重新排列，使相近粒子更可能读取相近网格场。cell ID 是空间分组的编号；粒子自己的 ID 则是身份。排序时位置、速度、权重和身份必须一起移动，否则会把一个粒子的速度配给另一个位置。

排序不是每步都越频繁越好，它也要计数、扫描、写入缓冲。先比较多次推进后空间局部性下降的损失，再与一次排序的成本相抵。频率是需要测量的参数，不是仅由线程数决定。

14.1　为什么粒子排序会同时影响多个内核

初始相邻粒子可能随时间分散。若同一线程块处理空间上相邻的粒子，它们读取的网格场更相似，沉积也集中到较小区域。按 cell 或 tile 分箱，可以增加场复用并减少局部累加的工作范围。但排序自身需要键、计数、前缀和、重排与缓冲，不能忽略这段时间。

cell_id[p] = locate_cell(position[p])
count[cell_id[p]] += 1                 # atomics or histogram primitive
offset = exclusive_scan(count)
reorder_all_particle_attributes(...)   # x, v, weight, id stay paired
push_and_deposit_by_tile(...)

重排必须覆盖所有粒子属性，包括物种、权重、随机数状态和旧位置。漏掉一个数组可能得到平滑但错误的结果。为粒子加入稳定 ID，在小样本测试中检查排序前后的属性配对。

14.2　局部沉积与竞争

基线使用全局 atomicAdd；改进版可在共享内存中累计一个 tile 的电流，再写回全局。tile 边界需要 halo 或明确的归属规则。粒子轨迹可能跨越 tile，特别是热电子；假设所有粒子每步只影响本 tile，必须有严格的时间步/形状支持约束，否则要拆分路径或回退处理。

重联会把粒子聚集到磁岛和电流层。均匀分布下表现良好的分块方案，可能在非线性阶段严重不均衡。计时至少选初始化、线性阶段、重联峰值和岛内聚集阶段的快照，而不是只用初态宣布吞吐。

14.3　一次完整 GPU 移植的顺序

先把粒子位置和速度常驻设备，完成 gather + push；再加入已验证的守恒沉积；最后把场求解、ghost 与诊断归约搬到设备。静电 FFT 的 plan 在时间循环外创建，场与粒子使用一致 stream 或显式依赖。每增加一个组件，都与 CPU 相同输入逐步对照。

训练 14 · 三种沉积策略的真实成本

比较未排序原子沉积、每步排序、每 K 步排序（K=2、5、10）。报告排序、推进、沉积、场更新及整个时间步耗时。再增加共享内存 tile 版本，分别测试均匀和聚集粒子。

验收：性能改进必须包含排序成本，且全部属性保持配对，电荷连续性与能量诊断无退化。若没有收益，保留较简单的基线。

论文：PSC：patch 与 GPU、VPIC 2.0。代码：PIConGPU 的粒子组织与沉积，先追踪数据流再阅读模板细节。

第十五章　验证：从单粒子到动理学不稳定性

学习目标：建立不会被一张“合理图像”替代的验证层级。

先理解：基准、收敛与物理验证

基准问题是具有明确设置与可比较结果的小问题；收敛性是改变时间步、网格或样本数后，研究量逐步稳定。程序验证（verification）问方程有没有算对；物理验证（validation）问所选方程是否足以描述实验或目标系统。二者需要不同证据。

冷等离子体振荡、Landau 阻尼和双流不稳定性分别检查不同动力学。增长率来自指数阶段的斜率；晚期饱和曲线不能拿来继续拟合同一个线性增长率。初学时先用有解析预期的简单算例建立信心，再扩展到重联。

15.1　代码验证与物理有效性不同

代码验证回答“是否正确求解选定的离散方程”；模型有效性回答“这些方程是否足以解释目标物理”。CPU/GPU 一致性是代码检查的一部分，但两个实现共享同一个符号错误时仍可能一致。解析解、制造解、守恒恒等式与跨代码对照各自补不同的缺口。

15.2　增长率拟合的两个陷阱

若幅值 \(A\propto\exp(\gamma t)\)，则 \(\ln A\) 的斜率是 \(\gamma\)；场能量正比 \(A^2\)，其对数斜率是 \(2\gamma\)。很多“增长率差一倍”来自混淆。另一个陷阱是拟合窗口：初始瞬态、线性增长、非线性饱和和噪声底不能用同一条直线描述。

分析脚本 要求显式输入拟合区间，并输出对数残差。它不会自动挑最漂亮的窗口。把起止时间分别移动，观察 \(\gamma\) 的稳定区；再比较网格、时间步、粒子数、速度域或形状阶数。复杂数据需要画图检视，而不是只接受一个回归系数。

15.3　一次只改变一种数值尺度

时间收敛时固定足够细的网格和粒子数；空间收敛时保持粒子噪声可比；噪声收敛时固定网格、增加每格粒子数并比较种子。对于非线性混沌动力学，逐点轨迹差异会放大，应比较统计量和物理阶段，避免要求每个涡旋出现在完全相同位置。

训练 15 · 完成一张验证矩阵

至少完成五项测试：CIC、Boris、真空波、冷等离子体振荡、双流增长。每项记录参考答案、误差度量、接受标准和失败例子。Landau 阻尼作为进阶，检查速度采样噪声或 Eulerian 速度网格复现时间。

验收：阈值有量纲说明与依据；提交一例确实被检查抓到的错误。只打印“PASS”而没有可追踪指标，不算验证报告。

练习：Smilei 的热等离子体、双流与 Weibel 教程；Gkeyll 的双流示例。比较不同离散表示对同一物理问题的验证方式。

第十六章　Harris 平衡与 GEM 重联基准

学习目标：构造有物理约束的电流片，并把重联复现变成可重复实验。

先理解：电流片与 Harris 平衡

电流片是磁场在较窄区域快速变化、因而需要较强电流的结构。Harris 平衡提供一种磁压与粒子压强平衡的理想电流片，粒子的漂移还必须产生所需电流。仅给一条 tanh 磁场曲线并放入任意粒子分布，通常不构成完整平衡。

重联磁场是跨片反向的分量；导向场是沿电流方向、通常不反向的分量。两者控制的轨道和尺度不同。GEM Challenge 是共享设置的重联基准，比较代码前要逐项核对参数，不能只因都出现磁岛就认为是同一问题。

16.1　从力平衡算出密度与电流

取电流片法向 y，重联磁场沿 x，电流沿 z。一个简单 Harris 设置为 \(B_x=B_0\tanh(y/\lambda)\)、\(n=n_h\operatorname{sech}^2(y/\lambda)+n_b\)。若两物种片内温度均匀，标量压强平衡要求下式成立。均匀背景密度可提供额外常量压强，但不能改变片内梯度平衡。

\[n_h(T_i+T_e)=\frac{B_0^2}{2\mu_0}\]\[J_z=-\frac{B_0}{\mu_0\lambda}\operatorname{sech}^2(y/\lambda)\]\[U_{zs}=-\frac{2T_s}{q_sB_0\lambda}\]

最后一行是此坐标与符号约定下片内漂移的一种标准 Harris 选择；它使物种电流之和满足 Ampère 定律。背景粒子应单独处理其漂移与分布。若反转坐标或定义 \(A_z\) 的符号，电流与漂移符号也必须同步改变。不要只初始化 tanh 磁场，再随意放一组无漂移 Maxwell 粒子。

16.2　边界条件是平衡的一部分

单个 tanh 电流片不能不加处理就沿法向周期连接；常见选择是适当的法向场/粒子边界，或构造周期双电流片。双片间距过小会相互影响。施加磁通扰动时从 \(\delta A_z\) 求离散旋度生成 \(\delta\mathbf B\)，有助于保持磁散度，而不是分别手改两个磁分量。

先做“不加触发扰动”的平衡保持测试，观察噪声与离散调整。无噪声粒子系统不存在于实际 PIC；微小自发演化不一定是实现错误，但强烈初始波、整体膨胀或能量漂移应先解释，不能全部算作重联物理。

16.3　怎样复现 GEM，而不是借一个名字

GEM Challenge 用共享初值比较不同模型对无碰撞重联的描述。复现时从原文及所选代码的正式输入逐项抄录盒长、片厚、背景密度、质量比、温度比、\(c/v_A\)、边界和扰动。本文不把未完整核对的参数拼成一份“标准输入”。质量比、归一化或边界不同的算例，应标明是变体。

先跑小规模确认诊断，再做分辨率检查。用重联磁通随时间、归一化重联率、流出速度和能量分配与参考比较。不同算法初始噪声可能移动触发时刻，必要时同时比较绝对时间和相同重联磁通下的结构。

训练 16 · 第一份重联复现包

选 PSC 或 VPIC-Kokkos，固定一个实际存在的 release 或 commit，按其文档编译并选电流片输入。保存源码版本、输入、归一化对照表、运行日志与五张诊断图。再改变 \(\Delta x\)、\(\Delta t\) 或每格粒子数中的一项。

验收：平衡测试、磁散度、Gauss 约束与能量账本通过；能说清与原始 GEM 的每一处差异。一个磁岛图不等于复现完成。

第十七章　从模拟输出识别重联机制

学习目标：测量重联率、能量转换与广义欧姆定律，避免把可视化当作机制证明。

先理解：磁拓扑与能量通道

二维磁场的 X 点附近，面内磁力线呈交叉分离的结构；O 点位于磁岛中心，周围磁通等值线闭合。重联率测量磁通连接怎样变化，不是磁岛图片看起来变快的速度。多岛时必须跟踪实际拓扑，初始中心未必仍是 X 点。

压力张量保留不同方向的压力及相关动量通量，比单一标量压强包含更多信息。广义欧姆定律把电场、流体运动、压力、惯性及碰撞联系起来；能量交换 \(\mathbf J\cdot\mathbf E\) 与“哪一项支撑重联电场”是相关但不同的诊断，应分别核对。

17.1　重联磁通与重联率

二维且 z 方向不变时，可用 \(A_z\) 描述面内磁场。明确采用 \(B_x=\partial_y A_z\)、\(B_y=-\partial_x A_z\) 后，定义 X 点与 O 点的磁通差，并固定符号或取绝对值。重联率可由该磁通差随时间的导数获得，常用 \(B_0v_A\) 归一化。多岛阶段需要追踪磁拓扑，不能一直在初始中心坐标取一个电场值。

在符合对称性与规范条件的二维设置里，X 点的 \(E_z\) 可与磁通变化互相校验；它并不在所有三维复杂场景中都是完整重联率。数值求导会放大输出噪声，先检查输出时间间隔，报告使用的差分或平滑窗口。

17.2　把电子动量方程放到同一位置

\[\begin{aligned}\mathbf E+\mathbf u_e\times\mathbf B={}&-\frac{\nabla\cdot\mathbf P_e}{en_e}\\&-\frac{m_e}{e}\left[\frac{\partial\mathbf u_e}{\partial t}+\mathbf u_e\cdot\nabla\mathbf u_e\right]\\&+\frac{\mathbf R_e}{en_e}\end{aligned}\]

这里 e>0，Rₑ 是电子动量方程中的碰撞/摩擦力密度。要比较右侧各项，必须将 nₑ、uₑ、Pₑ、E 和 B 插值到一致的位置与时刻，并明确差分算子。压强张量使用随机速度 v−u，而不是把总二阶矩直接当作热压强。

先验证各项加总的闭合残差，再讨论哪一项支撑非理想电场。电流片中的密度小、导数大，除以 nₑ 会放大统计噪声。空间平均、时间平均和粒子数都影响结果，应报告平均窗口并检查结论对窗口的敏感性。

17.3　能量转换与不可逆加热

J·E 描述电磁场与粒子之间的局部功率交换，不自动等于不可逆热化。体流能、热能、压强–应变、Poynting 通量及边界粒子能量通量需要组成完整账本。某处 J·E>0 可以同时存在能量随后流走或返回电磁场的情况。

分析电子分布函数时，先选择有物理意义的采样区域和速度坐标，例如沿局部磁场的平行/垂直分解。固定实验室坐标中的“温度各向异性”可能混入磁场方向变化或不同流束。把原始分布、矩量与采样粒子数一起保留。

第十八章　Streams、事件、Graphs 与精度选择

学习目标：用明确依赖组织流水线，在不改变物理误差的前提下优化整步执行。

先理解：stream 与 event

stream（流）是提交设备操作的有序队列：同一条流中的相关操作按顺序执行。多条流提供潜在重叠机会，实际是否重叠还取决于硬件资源、数据依赖和内存传输条件。stream 不是新增一张 GPU，也不能让依赖前一步结果的工作提前正确完成。

event（事件）可标记一条流执行到某个位置，供计时或其他流等待。主机提交内核后可能立即继续，所以“函数返回”只说明提交完成，不说明设备结果已就绪。先画出生产者和消费者，再用事件表达依赖，比四处插入全设备同步更容易解释。

18.1　先画依赖图

J 必须等粒子轨迹产生后才能沉积，E 更新必须等 J 完成。不同 stream 并不自动知道这些数据依赖。可以把主推进放在一个 stream，把已完成快照的诊断复制放在另一个 stream，用 event 表示快照已准备完成。

push_and_deposit<<<grid, block, 0, compute_stream>>>(...);
cudaEventRecord(particles_ready, compute_stream);
cudaStreamWaitEvent(diagnostic_stream, particles_ready, 0);
reduce_diagnostics<<<grid, block, 0, diagnostic_stream>>>(...);
// Do not overwrite data still read by the diagnostic stream.

双缓冲只有在读写对象真正分离时才有效。若下一步推进覆盖了诊断正在读的速度数组，即使复制本身异步正确，统计量也可能来自混合时间层。先用简单同步版本验证，再逐条删除不必要同步。

18.2　异步传输和图捕获各自解决什么

页锁定（pinned）主机缓冲是在传输期间保持驻留的主机内存；它有助于 DMA 传输，但占用过多会挤压系统可用内存。页锁定缓冲与异步拷贝有助于形成传输/计算重叠，但硬件、stream 安排和实际数据依赖决定能否同时执行。CUDA Graphs 把一组操作及先后依赖保存成可重复启动的计算图；固定形状、重复大量小内核的循环可评估这种方式，以降低主机逐次提交的开销。粒子迁移导致数量或缓冲改变时，图节点更新与捕获限制必须按当前文档处理。

当沉积已经占绝大部分时间时，Graphs 不会消除原子竞争。先根据时间线选择优化目标。对很长的单个内核，提交开销也可能可以忽略。不要用更复杂的异步结构掩盖一个本可直接修正的数据布局问题。

18.3　混合精度需要物理验收

一种待测试方案是粒子主体 FP32、能量和关键矩量 FP64 累加；但位置精度、强导向场下小扰动相减、低幅值 \(A_\parallel\) 与长期能量漂移可能对精度敏感。先做 FP64 小规模参考，逐项降低精度，检查重联率、增长率和闭合残差。

Tensor Cores 对某些稠密张量运算有价值，但普通 PIC 的散射沉积和不规则插值不自动变成矩阵乘法。若在 DG 局部算子或批量小矩阵中尝试使用它们，必须把数据重排成本与混合精度误差一起计入。不要为了使用某硬件单元而改变未验证的数值方法。

第十九章　多 GPU：从双卡边界交换到云端运行

学习目标：理解域分解、粒子迁移、守恒交换、通信重叠与 2 / 4 / 8 卡扩展性；附完整 MPI + CUDA 练习。

先理解：MPI rank 与数据分区

MPI 让多个独立进程交换消息。rank 是一个进程在通信组中的编号，不是 GPU 编号，也不是 CUDA 线程。采用“一 GPU 对应一 MPI rank”时，每个进程选择一张卡并管理自己的子域；节点内 rank 与整项作业的全局 rank 也可能不同，绑定设备时必须分清。

域分解把物理区域切成几块，halo exchange（边界交换）把邻居所需的场值送到 ghost cells。粒子迁移则转移跨出本子域的粒子所有权；沉积在边界上的贡献还可能需要相加。复制场值、累加沉积和迁移粒子是三种操作，不能都用简单覆盖处理。

Slurm 是云端/集群常见的作业调度器：脚本申请节点、GPU 和时间，调度器分配后才运行程序。节点是一台计算机，节点可以有多张 GPU。CUDA-aware MPI 表示 MPI 能接收设备指针，GPUDirect RDMA 是可能采用的直接网络传输路径，两者不是同一承诺。

19.1　一个 MPI rank 对应一张 GPU

先采用每 GPU 一个 MPI rank 的清晰映射。一个 rank 管理自己的网格子域、粒子、ghost cells、诊断与通信缓冲。节点内 rank 序号可以通过 MPI_Comm_split_type(..., MPI_COMM_TYPE_SHARED,...) 获取。调度器可能为每个进程只暴露一张 GPU，此时进程内设备编号是 0；若全部 GPU 可见，则按本地 rank 选择。

不要只打印“使用 GPU 0”。同时记录主机名、世界 rank、本地 rank 与 GPU PCI 标识或 UUID，确认同节点各 rank 没有意外挤到同一物理设备。CUDA_VISIBLE_DEVICES 会重新编号可见设备；逻辑序号不等于服务器上的物理序号。

19.2　先完成场的 halo，再迁移粒子

将二维域沿 x 分为 P 份，内部点只依赖本地数据，边界点依赖邻居的 ghost。场 ghost 通常需要复制相邻子域的有效值；粒子在共享网格边界沉积的电流贡献，则可能需要加和归并。把“复制场”与“累加沉积贡献”当作同一种交换，会丢失或重复电流。

附带 halo_mpi.cu 用周期一维扩散方程训练这一流程。它用解析的离散 Fourier 模验证每步结果：先发布邻居通信，同时计算不依赖 ghost 的内部；等待接收完成后计算边界。默认使用页锁定主机中转，可在不支持设备指针的 MPI 中使用。--device 才启用设备指针通信，必须先确认该 MPI 构建支持 CUDA-aware 功能。

\[\begin{aligned}u_j^{n+1}&=u_j^n+\alpha(u_{j-1}^n-2u_j^n+u_{j+1}^n),\\\alpha&=0.2\end{aligned}\]\[u_j^n=\left[1-4\alpha\sin^2\!\left(\frac\pi N\right)\right]^n\sin\!\left(\frac{2\pi j}N\right)\]

这个明确的离散解能检查跨 rank 索引与通信，不必把误差归因于 PDE 时间截断。程序不是 PIC，也不包含粒子迁移；它提供的是后续场交换可复用的、独立可验收的最小训练。

19.4　粒子迁移需要一份完整协议

  1. 分类：推进后按目标子域计算粒子归属；保留跨界前后轨迹，以完成当前步守恒沉积。
  2. 计数：为每个邻居生成发送数量，先交换计数，确认接收容量。
  3. 打包：把位置、速度、权重、ID 和必要随机状态一起写入连续缓冲。
  4. 发送与接收：使用明确标签；缓冲在通信完成前不得重用、重排或释放。
  5. 本地压缩与插入：删除已转移副本，把接收粒子放入拥有者子域，检查全局粒子数和权重。
  6. 归并边界电流：依据采用的轨迹分割和网格拥有规则，完成守恒贡献归并，再推进场。

“先迁移再沉积”或“先沉积再迁移”都可能在完整算法中成立，但各自依赖不同轨迹和 ghost 约定；不能混用。若一步跨越多个子域，只向左右邻居发一次不够。可以通过严格位移约束、重复转发或直接目标发送解决，并针对最快粒子测试。

19.5　CUDA-aware 不等于自动高速网络

CUDA-aware MPI 表示 MPI 能接受设备内存指针；它不保证使用 GPUDirect RDMA，也不保证通信/计算自动重叠。节点内可能经过 PCIe 或 NVLink，节点间可能走支持 RDMA 的网络或普通网络。用 nvidia-smi topo -m 和集群文档查看拓扑，再测设备缓冲 ping-pong 的延迟和带宽。

GPU 生产发送缓冲的 stream 必须先完成，MPI 才能读取。MPI 接收完成后再启动消费该数据的 GPU 内核。传统 MPI 通常不理解任意 CUDA stream 的隐式依赖；不要以为 Isend 是非阻塞就可以立刻覆盖发送区。通信进展还取决于 MPI 实现，时间线上没有重叠就不能声称实现了重叠。

19.6　强扩展、弱扩展和负载不均衡

\[\eta_{\mathrm{strong}}(P)=\frac{T_1}{PT_P}\]\[\eta_{\mathrm{weak}}(P)=\frac{T_1}{T_P}\]\[T_{\mathrm{step}}\approx\max_r(T_{\mathrm{compute},r}+T_{\mathrm{comm,exposed},r})+T_{\mathrm{sync}}\]

强扩展保持全局问题固定；弱扩展保持每卡工作量近似固定。上式中各时间量分别表示计算、未被隐藏的通信与全局同步。若同一科学问题已放不进单卡，以最小可运行卡数 \(P_0\) 作基线，效率写为 \(P_0T_{P_0}/(PT_P)\)，不要虚构 \(T_1\)。输出最慢 rank 时间，因为全局推进最终受慢者限制。

重联中的磁岛和电流片会形成粒子热点。均匀网格分域未必等工作量，动态 patch 迁移可以改善，但也增加元数据、通信和重分配成本。先记录每 rank 的粒子数与沉积耗时，确认不均衡确实显著，再评估动态平衡。

第二十章　Eulerian Vlasov：另一条动理学路线

学习目标：比较粒子采样与相空间网格，并建立一个可验证的 1X1V 训练方案。

先理解：Eulerian 与半拉格朗日

Eulerian 方法把分布函数保存在固定相空间网格上；PIC 则用运动的采样点表示分布。半拉格朗日方法从新时刻的网格点沿特征线倒推，找到旧时刻的出发位置，再插值旧分布。它避免显式跟踪全部真实粒子，但插值会引入自己的耗散与守恒问题。

算子分裂把位置平流和速度平流分开推进。式中的 \(\mathcal A_x\)、\(\mathcal A_v\) 分别表示这两步，半步—整步—半步的对称组合叫 Strang 分裂。理解顺序后，还需检查场在什么时刻求解，不能认为任意三步拼起来就自动二阶。

20.1　没有粒子噪声，也有数值代价

Eulerian 方法在 (x,v) 网格上直接离散 f。它可以清楚展示相混合与速度空间细结构，但需要面对高维存储、速度域截断、数值耗散、负值与守恒。没有宏粒子采样噪声不等于没有误差。细丝尺度逐渐变细时，固定速度网格最终会失去解析能力。

1X1V 足以训练 Landau 阻尼与双流，不足以表达一般二维电磁重联。2X2V 的 \(128^2\times64^2\) 个 FP64 值约 512 MiB，仅存一个分布数组；多个物种、Runge–Kutta 阶段与诊断很快增加用量。完整 3X3V 的维数灾难更严重，因此模型降维和稀疏/低秩方法需要自己的适用性分析。

20.2　用 Strang 分裂理解两种平流

\[\frac{\partial f}{\partial t}+v\frac{\partial f}{\partial x}+a(x)\frac{\partial f}{\partial v}=0\]\[\mathcal A_x(\Delta t/2)\to\mathbf E[\rho]\to\mathcal A_v(\Delta t)\to\mathcal A_x(\Delta t/2)\]

x 平流是在每个速度切片上平移分布；v 平流是在每个空间点按局部加速度平移速度分布。静电情况下 v 平流保持该位置的密度积分，适当的时间中心组织可构造二阶分裂。但子步骤的插值与边界处理仍决定质量、正性与耗散。

for j, velocity in enumerate(v):

# rho = ion_density - velocity_integral(half); then solve E
for i, electric in enumerate(E):

这段是教学骨架，不是已验证求解器。线性插值会引入耗散；速度边界的零外推可能损失质量。要做精确阻尼率研究，应进一步选择守恒半拉格朗日、有限体积或 DG，并验证其数值性质。

20.3　GPU 上的主要工作不同了

PIC 的困难常是散乱沉积与粒子迁移；Vlasov 的困难常是高维数组平流、内存带宽与分布式转置。不同方向的连续访问需求可能冲突。DG 局部算子可能具有可复用的规则小矩阵结构，但跨单元通量和阶段数组仍消耗带宽。先从 1X1V 的一个方向平流建立 GPU 原型。

第二十一章　回旋动理学、微撕裂与聚变重联

学习目标：理解从 Harris 电流片到托卡马克微撕裂之间必须补上的物理。

先理解：回旋中心、MTM 与宇称

强磁场中粒子绕磁力线快速回旋，回旋中心是去掉这一快速圆周运动后描述较慢运动的位置。回旋动理学依靠频率、尺度和扰动幅度的排序推导，适合某些低频磁化问题；它不等于把普通 PIC 的时间步调大。

撕裂/微撕裂模与磁拓扑变化有关，MTM 常牵涉电子动力学及温度梯度等驱动，实际驱动需逐篇核对。宇称是模结构关于某个对称位置的奇偶关系：镜像后同号或反号。比较势与矢势的宇称可以辅助识别模态，但必须先统一坐标、相位和归一化，不能只看两条曲线是否相似。

21.1　回旋平均换取更长时间尺度

强磁化、低频与适当小扰动排序下，可以消去快速回旋相位，使用回旋中心分布描述动力学。常见排序涉及 \(\omega/\Omega_i\ll1\)、平行与垂直尺度分离以及受控扰动幅度。它不是“把质量比调小”的别名，而是一套经过推导的降维方程、极化/磁化响应与守恒结构。

电磁问题中 \(\phi\)、\(A_\parallel\)，以及是否保留 \(\delta B_\parallel\)，会影响所覆盖的物理。电子平行动力学、碰撞算子和背景梯度同样重要。Brizard–Hahm 综述 可用于建立整体理论地图，不要求第一次就从头推完全部变分推导。

21.2　强导向场不自动等于 GK 适用

Muñoz 等的 PIC/GK 比较 专门研究强导向场电流片中的适用范围，并指出初始化剪切流、\(\beta\) 和局部流动对比较的影响。阅读时应提取其平衡、排序和诊断，而不能把某个算例中的导向场比值当作所有聚变问题的通用阈值。

对于你关心的研究，关键问题是：需要全轨道电子扩散区，还是低频电磁不稳定性及输运？若后者更重要，电磁回旋动理学可能比把完整装置硬塞进显式 PIC 更有效。若局部非绝热轨道是核心，则需保留能描述它的模型并承担相应尺度成本。

21.3　微撕裂不是任意电磁涨落

识别 MTM 时，应结合模宇称、电子温度梯度驱动、\(A_\parallel\) 结构、频率、碰撞依赖及几何响应。只看到磁扰动或电子热通量增加不足以命名微撕裂。不同参数区间的驱动机制可以不同，不能把“MTM 必须在有限碰撞率处最强”当作无条件规则。

按顺序阅读 Applegate 等的 MAST 微撕裂研究、Dickinson 等的 pedestal-top MTM、MAST 非线性 MTM 与随机层研究。每篇制作同一张参数表：几何、\(\beta\)、碰撞率、梯度、磁剪切、质量比、速度空间分辨率和诊断。不同论文之间的差异本身就是学习内容。

21.4　从线性模到非线性输运

先做 \(k_y\) 扫描，拟合增长率与实频率，检查沿场线和速度空间收敛。再比较 \(A_\parallel\) 与 \(\phi\) 的模结构和宇称。非线性阶段检查磁岛重叠、磁力线统计与电子热通量；同时区分磁涨落和静电涨落对输运的贡献。通量管、全局径向域和装置几何并不是可以无成本互换的选项。

第二十二章　碰撞、隐式方法与尺度分离

学习目标：知道何时需要新增物理或算法，以及它们必须通过哪些守恒检查。

先理解：碰撞、隐式与扰动权重

碰撞算子描述分布因相互作用而松弛；它应满足对应模型要求的粒子数、动量与能量性质。隐式推进把未知的新时刻量也放进方程，通常需要迭代求解。更大的稳定步长可能伴随更昂贵的每步成本，而且稳定不代表所有快物理仍然准确。

\(\delta f\) 方法在已知背景 \(f_0\) 附近演化扰动。计算粒子携带的权重反映扰动贡献，权重方程要从模型推导；允许负权重并不代表负数真实粒子。隐式、碰撞与扰动方法分别改变不同部分，应一次加入一种并重新验证。

22.1　把碰撞写成可验证的交换

聚变重联不总是完全无碰撞。电子电阻性、半碰撞电子层、微撕裂驱动与能量弛豫都可能涉及碰撞。简单 Krook 松弛、BGK、Fokker–Planck 和二元 Monte Carlo 算法保留的守恒量不同，不能仅调一个“碰撞频率”就认为模型等价。

首先用均匀无场问题测试两个物种的温度弛豫、各向异性弛豫、总动量与总能量。区分物理摩擦和随机采样误差。粒子配对、随机数状态和 MPI 分域变化不应引入系统性偏差，尤其在每格粒子数不足时。

22.2　随机数也是可复现性的一部分

每个线程重复使用相同种子会产生相关噪声。为粒子或配对建立可追踪的随机状态；重排和迁移时一起搬运，或使用基于稳定 ID、时间步与子步骤的计数式方案。全局 rank 改变后随机路径不必逐位相同，但统计性质与守恒应可比。

22.3　隐式方法降低某些限制，也增加求解工作

隐式电磁或半隐式方法可以放宽某些显式稳定性限制，但必须解析目标物理的时间尺度。即使某时间步数值稳定，也可能抹掉想研究的电子动力学。每步的非线性迭代、线性求解与预条件开销，需要和减少的总步数一起比较。

在 GPU 上，稀疏求解、全局归约与跨节点通信可能成为主要瓶颈。不能只报告粒子推进变快。求解容差也是物理误差预算的一部分：把容差收紧，若能量或重联率仍明显改变，说明迭代误差还未受控。

22.4　混合模型与 \(\delta f\) 的合理入口

若目标是离子尺度而电子细节可由受控闭合表示，可评估混合动理学。若目标是已知背景附近的小扰动，可进一步学习 \(\delta f\) 方法降低噪声。二者都需要单独的方程推导和验证，不能在 full-f 电磁 PIC 中随意删一组变量后沿用原有守恒结论。

训练 22 · 增加一种物理，一套新检查

只选择碰撞、隐式场推进或 \(\delta f\) 中的一项。写明新增方程与离散算法，先完成均匀或线性测试，再放进重联。对碰撞扫描 \(\nu\Delta t\)；对隐式方法扫描步长和求解容差；对 \(\delta f\) 检查背景与扰动恢复。

验收：新增模块的收益有物理或性能证据，守恒量与适用范围有明确说明。没有验证时，保持原始模型作为可信基线。

资料：Gkeyll 的碰撞模型与守恒说明；Smilei 二元碰撞教程。结合上一章文献讨论为什么不同 MTM 参数区间需要不同碰撞处理。

第二十三章　把训练收束成三个研究项目

学习目标：从“学完 CUDA”转向可以复核的物理结果与性能成果。

先理解：参数扫描与控制变量

参数扫描是在一组明确控制条件下改变一个或少数参数，比较同一组诊断。改变导向场时，固定重联场归一化与固定总场归一化可能对应不同实验。先列“改变什么、保持什么、由此被动改变什么”，比一次提交很多云作业更重要。

验证路径可以有两层：先用便宜的小域确认机制和收敛，再选有代表性的参数做更大域、更高质量比或更多维度。第二层要说明与第一层哪些量可比，不能把不同离散误差下的变化全部归结为新物理。

项目 A　强导向场重联中的电子非理想电场

从成熟全动理学 PIC 的已验证电流片开始，固定 \(\beta\)、质量比、片厚、边界与触发方式，选择一个导向场扫描。注意保持哪些归一化量不变：若总磁场变化而温度不变，总场 \(\beta\) 也会变化。把这一差别写进设计，不要同时无意扫描多个物理量。

主要输出为重联磁通、率、电子层宽度、电子压强张量与惯性项、粒子分布。至少在两个扫描点做额外数值收敛。性能工作围绕实际最昂贵的沉积或诊断内核，优化后重新检查欧姆定律闭合。该项目可衔接 PIC/GK 适用性研究，但不能直接声称预测托卡马克全局输运。

项目 B　聚变微撕裂的线性到非线性路线

选择一篇 MAST 或与你装置参数相关的电磁 GK 论文。第一阶段复现一个线性模式；第二阶段做碰撞率、电子温度梯度或磁剪切中的一维扫描；第三阶段才考虑非线性磁随机化与热通量。每阶段都要保留几何和数值分辨率表。

性能工作可以是速度空间算子、通信、场求解或诊断的 GPU 优化，取决于实际代码。你不必从零写完整 GK 求解器才能做计算研究；在成熟代码中抽出一个代表内核，验证等价实现，再回到完整应用测收益，往往更可控。

项目 C　面向重联负载的 GPU 沉积与多卡效率

用同一个正确的守恒电流算法，对比粒子排序间隔、tile 尺寸、局部累加和通信安排。测试均匀态与真实重联非线性快照，保持物理输入、精度和诊断一致。若目标是计算方法论文，速度以外还需证明守恒、误差与不同负载下的适用性。

云端先完成 2 卡正确性，再进行 4/8 卡强弱扩展。输出卡时、总耗时、最慢 rank 分解与检查点恢复成本。某个内核局部加速十倍而整步只快 5%，仍是有价值的分析，但应如实报告。

第二十四章　24 周训练表与阅读方法

学习目标：把全书变成每周有代码、图和解释的持续训练。

先理解：什么叫别人能复现

可复现不只是把源码上传：还要给出确切版本、输入参数、依赖、编译与运行命令、随机种子、数据处理脚本和预期检查结果。随机粒子模拟未必逐位一致，但统计量、误差范围和物理判断应能重复得到。

把一次运行想成“输入 → 原始输出 → 诊断 → 图 → 结论”的链条。每张关键图应能追溯到具体运行，每个拟合窗口应写在脚本参数中。性能结果也要记录 GPU 型号、卡数、并行布局和是否包含初始化及输出，这样云端资源改变后才知道比较是否公平。

24.2　每篇论文读三遍，但目的不同

第一遍只看问题、结论图与适用模型，判断与研究合同的关系。第二遍提取方程、参数、边界、初始化和诊断，做成复现表。第三遍围绕一个关键结果追踪证据：它用什么分辨率、如何拟合、误差是否可能解释差异。读完要留下一个可以编码验证的小问题。

不要用“本文首次提出一种高效方法”这样的句子替代阅读。写出加速了哪个循环、基线是什么、在哪种硬件与负载下、牺牲了什么，以及这件事如何影响你的重联计算。理论论文则把假设、排序与关键推导保留下来。

24.3　视频、文档与代码各自怎么用

视频用于建立直觉，官方文档用于确认 API 与限制，代码实验用于发现自己是否真的理解。看 OLCF 一讲后，应离开视频写一个最小实验；遇到工具版本差异，回到当前官方文档。物理课程补充概念，不能替代原始论文中的参数与模型。

优先阅读顺序：Birdsall–Langdon 的静电部分 → CUDA 入门与性能工具 → Esirkepov 守恒 → GEM 基准 → PSC / VPIC 的实现 → PIC/GK 比较 → MAST 微撕裂线性与非线性工作。资料索引标明每项的用途，避免把长书单当作必须一次读完的任务。

代码库与官方教程：选择一条主线深入

  1. NVIDIA Accelerated Computing Hub · CUDA C++。用于现代 CUDA 基础练习，与 OLCF 的历史课程互补。
  2. WarpX · Electromagnetic PIC，以及 代码库。用于学习电磁算法、工程验证与高性能组织；具体重联算例和物理模块应另行确认。
  3. Smilei · PIC algorithms。适合交叉检查推进、时间层、插值和沉积概念。
  4. Smilei Tutorials。先做热等离子体、双流/Weibel，再看并行与碰撞；教程名称不是对本站 CUDA 实现的验证。
  5. PSC。重联全动理学路线可优先阅读。已核对仓库存在 Harris 源码入口；构建与输入语法以固定版本为准。
  6. VPIC-Kokkos 与 官方编译说明。用于学习大规模全动理学、Kokkos 与 GPU；从官方 sample/deck 开始，先验证小规模。
